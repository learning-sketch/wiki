**关键 synthesis（综合三家差异）**

1. **三家两派**：MindIE + vLLM 同属 hash table 派（差别仅在抽象层数：MindIE C++/Python 双段 vs vLLM 全 Python 单段）；**SGLang 唯一用 trie**（`RadixCache` 8+ 实现并存）。
2. **跨语言 hash 等价约束是 MindIE 独家设计税**——C++ `HashCombine` 与 Python `hash_combine` 必须逐位等价；vLLM/SGLang 全 Python 单语言无此约束。
3. **SGLang `init_cache_with_memory_pool` 内 8+ 路工厂分支**（[scheduler.py:783-890](d:\design\sglang\python\sglang\srt\managers\scheduler.py)）覆盖 RadixCache / HiRadixCache / RadixCacheCpp / SWA / Mamba / HiMamba / Unified / LMC / ChunkCache + SessionAware 包装——**这种"接口分支爆炸"是 SGLang 把 prefix cache 当成"前端核心抽象"而非"后端实现细节"的设计结果**。
4. **vLLM 是唯一 hash function 可插拔的家**（4 种：sha256 / sha256_cbor / xxhash / xxhash_cbor，[hashing.py:82-100](d:\design\vllm\vllm\utils\hashing.py)）——为 KV events 跨进程消费方提供可选稳定 hash。MindIE 锁死 boost-style；SGLang trie 不用单点 hash。
5. **API 命名陷阱**：相同语义在三家用了 3 种命名（`GetCommonComputedBlockIds` / `find_longest_cache_hit` / `match_prefix`）——anchor cross-check 直接证明三家 prefix cache 抽象相互独立设计（**6 处 N/A 强论断**全对全独立）。
6. **eviction 策略只有 SGLang 真 pluggable**（CLI 默认 3 种 `{lru, lfu, slru}`，`evict_policy.py` 注册 7 类可扩展）；MindIE / vLLM 的 LRU 是结构性绑定。
7. **多层存储设计哲学**：vLLM connector 14 backend 是开放生态；SGLang HiCache 7 后端 + write-back ack 最贴近"传统数据库 buffer pool" 语义；MindIE MemPool 2 后端最简但高内聚。

**Lessons learned**

1. **"父对比页 §X 铺种子 → 子对比页深化" 模式再次印证 ROI 最高**：本轮 prefix-cache.md 直接基于 [comparison/topics/kv-cache.md §2 Prefix cache 数据结构对比](../comparison/topics/kv-cache.md) 已铺的 3 行表 + 三家详细页（mindie + vllm + sglang/mem_cache.md），未启动任何 subagent，主 agent 直接写 + 少量补 grep（SGLang `disable_radix_cache` / `radix_eviction_policy` / `init_cache_with_memory_pool` 工厂分支）。耗时短而信息密度极高。
2. **"跨家命名 3 选" 是 cross compare 的高价值 synthesis**：相同语义 `GetCommonComputedBlockIds` / `find_longest_cache_hit` / `match_prefix` 在三家完全不同——单看任一家都看不出"独立设计"，cross compare 的 anchor reverse-scan 才能精确证明（**6 处全 N/A 强论断**就是这种正交性的最强证据）。
3. **"hash table vs trie 三家两派" 作为顶层 synthesis 在 [comparison/topics/kv-cache.md](../comparison/topics/kv-cache.md) 已建好种子**：本轮深化只是把这个一句话 synthesis 展开成 11 子维度的对照表 + cheat sheet + 6 anchor 验证。**这种"种子句子 → 完整对比页" 转换是良性 wiki 演化路径**——避免一开始就写完整对比页（容易过早抽象）。
4. **同名陷阱必须 anchor cross-check 后显式标注**：MindIE 全树 grep `RadixCache` 命中 1 处（[`tokens_knowledge_base_cache.py`](d:\design\MindIE-LLM\mindie_llm\text_generator\plugins\memory_decoding\tokens_knowledge_base_cache.py)），**实际是 memory_decoding plugin 内部 unrelated 类，与 prefix cache 主体无关**。本轮 §10 anchor 表显式标"同名 unrelated 类 / 命名陷阱"，避免未来 reader 误以为 MindIE 也有 trie 派。
5. **数字论断要复核**：`comparison/topics/kv-cache.md §3` 之前写 "SGLang 7 种 eviction"，本轮验证 CLI 默认仅 3 种（`server_args.py:206 RADIX_EVICTION_POLICY_CHOICES = ["lru", "lfu", "slru"]`），其余 4 种是 `evict_policy.py` 注册类但需 `add_radix_eviction_policy_choices` 扩展。**精确说**："注册 7 类策略但 CLI 默认 3 种可扩展"。本轮在 prefix-cache.md `[!warning] CONTRADICTION` 显式 sync。
6. **dimensions.md 占位要按 ROI 升级，不要长期 TODO**：`§dim-prefix-cache` 之前 SGLang cell 写"待 ingest 确认"——本轮深化时一并补完整分支描述 + CLI 选项 + 深度链接。**dimensions.md 是新 agent 的快速地图，长期 TODO 占位会拖慢未来 query**——建议每次 compare 页 ingest 时主动检查相关 §dim 是否需要 sync 升级。

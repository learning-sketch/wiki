### 关键新发现

1. **MindIE 的 PD 是同步的，vLLM/SGLang 都异步** —— 这是 verify pass 修订的最重要 synthesis：原页面写"D pull / P push"对比，verify 后改为"sync vs async"对比。MindIE D pull 是 `for x in p_d_infos: pull_blocks(x)` 阻塞循环（[generator.py:164-175](d:\design\MindIE-LLM\mindie_llm\text_generator\generator.py)），如果 D 接到的请求涉及多个 P 副本，逐个串行等。**这是 MindIE PD 优化最大的潜在改进点**。

2. **MindIE Layerwise PD 不支持 prefix caching** —— [lwd_self_attn_block_manager.h:27](d:\design\MindIE-LLM\src\block_manager\lwd_self_attn_block_manager.h) 的注释明示。如果 layerwise 流量有高 prefix 重复率，需要早评估限制。

3. **SGLang cached_tokens 4 元组直接传 HiCache 三层统计** —— 比 vLLM 的 `KVCacheEvent` 更细。D 端可以做"P 端命中率监控"，按 P-side device/host/storage 三层命中率切换路由。

4. **vLLM `MultiConnector` 不是 P+D 合并** —— 之前在 §2 表格里写"通过 `kv_role=both` + `MultiConnector`，间接支持"是错的；MultiConnector 实际是多 storage layer wrapper（mooncake_store + LMCache 同时存）。原页面已修订。

### 新的 critical contradiction

> **vLLM `do_remote_prefill` 命名反直觉**（[NIXL scheduler.py:282-302](d:\design\vllm\vllm\distributed\kv_transfer\kv_connector\v1\nixl\scheduler.py)）：在 D 端的 req 上意为"让本地 D 去远端 P 拉 prefill"——字面读起来像"本地做 remote prefill"。这可能是上层用户配置时的常见踩坑。注释只说语义不解释命名。
